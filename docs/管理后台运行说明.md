# 赛事补给协同助手：本机管理后台

已实现员工/管理员两角色JWT鉴权、共享知识库、数据库提示词模板、对话审计，以及员工SSE聊天。管理员页面使用Jinja2服务端渲染与原生JS，员工仍只有聊天页。

## 安装与启动

在仓库根目录执行PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m race_supply.manage admin --role admin
.\.venv\Scripts\python.exe -m race_supply.manage staff --role employee
.\.venv\Scripts\python.exe -m uvicorn race_supply.web:create_app --factory --host 127.0.0.1 --port 8000
```

创建账户时交互输入12至256字符密码，不提供默认账户。访问`http://127.0.0.1:8000/`登录，管理员点击“管理后台”，或访问`/admin`。

未配置对话模型时可使用聊天页默认的“仅检索”模式。本次后台实现不改动或测试现有API密钥。对话配置沿用`.env.local`；本地向量模型首次使用需下载。

## 页面与接口

| 页面 | 地址 | 功能 |
| --- | --- | --- |
| 管理概览 | `/admin` | 资料处理状态、待复核数量 |
| 知识库 | `/admin/knowledge` | 上传Markdown/PDF、处理进度、文档列表 |
| 文档详情 | `/admin/knowledge/{id}` | 原文、页码/切片、失败原因、发布、归档、重建、软删除 |
| 提示词 | `/admin/prompt-editor` | 编辑、立即启用、版本记录、回滚 |
| 对话审计 | `/admin/audit` | 按员工、时间、标记状态筛选；查看来源与模板版本；人工复核 |

接口沿用确认清单：`/auth/login`、`/auth/me`、`/auth/logout`，`/admin/documents`及详情/chunks/reindex/publish/archive，`/admin/jobs/{id}`，`/admin/prompts/current`、`/admin/prompts/versions`及activate，`/admin/conversations`及详情，`/admin/messages/{id}/flags`、`/admin/flags/{id}`。后台接口仅管理员可访问；旧`/api/login`等登录入口为兼容别名。

所有修改请求需携带`X-Requested-With: race-supply`，同源页面自动携带；浏览器跨站请求被拒绝。登录JWT保存在HttpOnly、SameSite=Strict Cookie中，15分钟有效；签名算法固定HS256，校验签发者、受众、有效期及SQLite会话白名单。退出立即撤销白名单；角色每次从数据库读取。过期后需重新登录，当前没有自动刷新令牌。

## 文档生命周期

1. 上传最大1MB的Markdown或文字型PDF，文档为草稿。
2. 持久化任务记录，后台解析、按标题/段落切片、向量化，保存FAISS索引与SQLite切片元数据。
3. 处理成功后，管理员核对资料性质与版本，再人工确认发布。
4. 新版发布自动归档同系列旧版。重新索引先撤回当前版本，成功后仍需再次发布。
5. 软删除立即退出后续检索，保留原件、索引及历史审计；不等同于物理清除。

PDF限50页、提取文本最多10万字符，通过带30秒超时的子进程提取文字。加密PDF拒绝处理，空白/图片页提示先OCR或提供文本，不自动假装识别成功；不提供扫描件OCR服务。原始PDF页码与提取文本行号均可追溯。PDF解析隔离进程不等于生产级文件沙箱。

索引任务状态：queued → parsing → embedding → ready；失败记录中文原因。服务重启时，未完成任务明确标记为失败，管理员重新索引。当前使用本机后台任务，不是分布式队列，**仅运行一个Uvicorn worker**。

## 提示词与审计

数据库初始模板为赛事补给领域文本。管理员修改生成新版本，下一次问答读取当前版本；并发编辑冲突返回409，防止覆盖他人的修改。正在生成的回答使用开始时的模板快照。助手消息保存`prompt_version`，历史旧记录可能为空。

权限过滤、相关性门槛、JSON回答结构与原文摘录校验由程序维护，模板编辑不改变这些代码检查。原文摘录一致不等于业务结论在语义上正确，仍需人工评测。

审计查询参数：`employee_id`、`from_ts`、`to_ts`（Unix秒）、`flag_status`。最多返回200个匹配会话。标记类别包括疑似违反补给规则、资料不足、引用异常、其他；状态为待复核、人工确认、已排除。必须填写标记理由及复核说明，操作账户和时间留痕；不由模型自动认定违规。

## 数据与验证

`work/web/race_supply.sqlite3`保存本机数据；`work/web/jwt.key`为自动生成且持久化的本机签名密钥；上传原件与任务保存在数据库。`work/`和密钥已被Git忽略。新增字段采用兼容迁移，升级后旧登录凭证需重新登录。备份时应一致备份数据库与签名密钥；生产部署前需另行落实备份、留存和清理政策。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m race_supply.phase1_rag --self-test
```

测试使用隔离SQLite、合成PDF、HTTP/向量任务替身，不调用真实对话API。真实GPU建库另通过浏览器上传演练Markdown验证。正式制度、换算口径、审批权限与资料保留期限仍需业务方提供并确认，不由系统编造。
