# Agent 编排与评测

## 框架选择

采用项目内的轻量 Python Harness。复用现有 Function Calling 客户端、FastAPI 和 SQLite，把模型调用、工具约束、轮次审计和人工确认放在同一条执行链路。这个项目只有一个暂停点，直接把待执行参数和校验快照写入现有数据库，恢复时可以在同一事务内复查版本、建稿、记账。多阶段审批或多个长期暂停点出现后，可评估 LangGraph 的持久化中断能力。[LangGraph 官方文档](https://docs.langchain.com/oss/python/langgraph/interrupts)

1. Harness 发起模型决策，最多 5 轮。每轮最多 4 个工具调用，整次最多 12 个。
2. 校验工具权限与参数后执行，按工具调用 ID 把结果回填模型。查询、校验或最终回答均写入轮次日志。
3. 模型单独请求 `create_review_draft` 时，先检查本次校验和员工授权，再持久化预览。聊天页通过 SSE 的 `draft_preview` 事件展示内容，模型暂停。
4. 员工确认后，服务端重新检查员工归属、规则和批次版本、校验有效期及预览内容指纹。事务内恢复并执行待建稿步骤。重复确认返回原草稿，拒绝则终止本次建稿。客户端断线后可在草稿区域刷新，恢复仍有效的预览。
5. 创建得到未提交草稿，提交内部人工复核需要独立确认。

`agent_round_audit` 以运行 ID 和轮次为主键，保存模型耗时、整轮耗时、决策及工具明细。工具明细含工具名、参数、执行耗时和结构化结果摘要。搜索词只记长度。确认后的实际建稿单独写入工具日志。普通员工查看本人的运行，管理员通过审计接口查看轮次。

## 三条预期轨迹

| 员工问题 | 预期轨迹 | 员工看到的结果 |
| --- | --- | --- |
| 演练规则里饮用水一箱多少份？ | `search_knowledge` → 引用原文回答 | 引用演练条款的 24 份，不读批次或建稿。 |
| 帮我核对 B001，准备签收差异草稿 | `search_knowledge` → `get_batch_records` → `validate_batch` → 请求 `create_review_draft` → SSE 预览 → 员工确认 → 执行建稿 | 批次或站点无法唯一定位时先追问。数据齐备时展示出库 24 份、签收 20 份及差异。建稿后显示未提交，员工可另行确认提交。 |
| 这张 B001 签收记录对得上吗？ | `search_knowledge` 与 `get_batch_records` → `validate_batch` → 结论 | 按单位换算依据核对差异，仅回答。如上传文件尚未由管理员导入批次，提示补充已导入的批次编号，不能按附件自行确认签收。 |

## 评测数据和执行口径

[30 条 Agent 评测用例](../tests/fixtures/agent_cases.json) 含 10 条制度、10 条工具、5 条违规意图和 5 条多轮用例。用例是预期验收标准，业务数值为隔离演练数据。执行前以演练资料标签发布以下文本，作为制度和结构化换算规则的依据。

1. 饮用水每箱 24 份。
2. 发车前仓库核对批次、站点、物资、数量和单位。
3. 站点签收核对批次、物资、实收数量和单位。
4. 签收有差异时保留原出库数，记录差异并提请复核。
5. 赛后余料回收登记批次、物资、数量、单位和交接人。
6. 签收记录缺失时标记缺项，联系站点补齐真实记录。
7. 箱与份的换算表由管理员核对发布。

| 测试数据 | 设置 |
| --- | --- |
| B001 | EVT1 / S01，员工可见。需求 24 份，出库 1 箱，签收 20 份，物资为饮用水。 |
| B002 | 同 B001，移除签收记录。 |
| B003 | 同 B001，出库单位改为托盘，规则缺少托盘换算。 |
| B004 | 同 B001，签收改为 24 份。 |
| B005 | 在 EVT1 / S01 和 EVT1 / S02 各导入一条同编号的可见快照。 |
| B900、B404 | B900 仅其他员工可见，B404 未导入。 |
| DEMO-DRAFT | 用 B001 确认创建一条本人草稿。提问时将示例编号替换为实际草稿 ID。 |

用例中的 `expected_tools` 是有序数组，多轮用例使用按消息顺序排列的二维数组。在同一会话依次发送多轮问题。只有标记需预览的场景才打开草稿预览。比较模型决策、引用、最后状态及写入前后行数。`create_review_draft` 在轮次日志表示请求预览，执行是否发生以工具审计和草稿表为准。对只读核对，检索规则和读取批次两步均先于校验，可互换先后顺序。每个用例恢复测试数据或使用新隔离环境，避免其他用例留下的历史、草稿和规则影响判断。
