# 设计说明

## 背景

训练场景希望减少补给站配送批次的重复核对，提高服务可追溯性。仓库尚未纳入角色访谈证据；当前流程是待验证假设。

## 当前设计

采用 Python 标准库，将命令行、核心业务与通用校验分离。需求记录不可变，业务函数返回新记录，由调用方保存。

```text
待调度 → 指定配送人员 → 已派单 → 指定签收人员 → 已签收
```

记录包含站点、物资、正整数数量、状态、配送人员和签收人员。演示采用单物资、全量签收，数量单位在物资名称中注明。

## 当前边界

没有数据库、网页、登录鉴权、库存扣减、部分签收、取消、配送批次编号、版本核对或审计日志。人员字段仅用于演示，不构成权限控制。

## 需要访谈确认

- 重复核对发生在哪个环节，有哪些实际清单和异常案例？
- 配送批次、站点、物资和清单版本如何关联？
- 谁能修改清单，交接后责任何时转移？
- 单位、少收、缺件和重复配送如何处理？
- 网络、数据更新和系统接口有哪些限制？
- 首期试点范围、核对耗时和差错率基线如何确定？

后续顺序：访谈与证据整理 → 确认需求与验收条件 → 选择最小功能 → 界面与存储 → 小范围验证。
