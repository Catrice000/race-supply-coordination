# 赛事补给物资与站点协同系统需求定义

版本 v0.1 · 2026-11-06 · 评审稿

## 1. 业务目标与依据

首期建议验证一个配送批次在库存核对、装车、站点签收等交接点能否减少重复核对，并保留来源与人工确认。先在同一批次内选择一至两个交接点做重点观察，验收样本仍需覆盖出库至站点的追溯链。重点观察点、试点批次和站点名单由业务负责人确认。

现状流程为站点需求 → 库存核对 → 装车 → 签收 → 余料回收。重点案例采用访谈中的模拟异常：站点临时扩充，追加物资未同步到配送单，现场只能冻结复核结论并回查原始版本和经手人。异常发生频次、核对耗时及责任归属待补采。

依据：[六角色访谈与36条事实](discovery/discovery-report.md)、[项目四份资料](discovery/brief/)、[四轮访谈原文](discovery/interviews/)、[候选需求](requirements.md)、[现状流程图](业务现状.jpg)、[改造流程图](AI数智化流程图.jpg)。下文 fNN 为原报告事实编号。材料为合成演练，本文优先级和新增验收判据供项目评审。

## 2. 痛点与改造优先级

| 痛点 | 首选改造 | 优先级与理由 |
| --- | --- | --- |
| 单据分散，跨工具编号不一致，反复找原记录 | 先按批准的关联键匹配。AI 可在无法唯一匹配时提出候选来源，人员逐项核验 | 确定性追溯 P0。AI 候选匹配 P2，需另有标注数据 |
| 仓库按箱、站点按份，数量容易被误判 | 用经批准且有版本的换算规则计算差异。AI 可解释差异和引用规则 | 换算及拦截 P0，AI 解释 P1 |
| 追加需求未同步，当前单据看不到旧版本 | 规则识别版本冲突和缺项。AI 将已识别异常整理为带原行引用的核对清单 | 版本控制 P0，AI 整理 P1 |
| 班组重复询问批次状态和处理口径 | 员工在聊天中查询已授权的批次，AI 根据检索到的台账、单据与规则作答 | P1，依赖来源和权限通过 P0 验收 |
| 读取失败或资料过期时容易误报最新状态 | 保留并标记最近成功快照，触发人工核查 | P0，属于系统控制 |
| 出现争议时难以定位谁查过、谁确认 | 保留原始数据版本、查询记录、AI 建议与具名复核结果 | P0，属于验收硬约束 |

P0 为试点必备控制。P1 为首期拟验证的 AI 能力，P0 通过后启用。P2 为后续验证项。P1 可用的前提是模型只接收允许使用的脱敏数据，且模型不可用时规则核对与人工复核仍可继续。

## 3. 需求规格与边界

| 需求编号 | 角色及触发 | 输入与处理规格 | 输出与异常边界 |
| --- | --- | --- | --- |
| RD-01 · P0 批次关联 | 数据维护人员导入脱敏只读样本 | 保存站点演练编号、物资标识、单位、批次、签收时间、来源文件与行号、版本。依据批准关联键连接出库和签收，区分缺失与未确认 | 每条样本显示关联路径。无匹配、多匹配或关键字段缺失时，保留原行并进人工队列 |
| RD-02 · P0 单位核对 | 员工核对同批次数量 | 读取经授权确认的物资换算率、生效范围、版本及依据。计算保留原单位、换算过程和标准单位 | 展示差异与引用。无规则、规则冲突或过期时拦截，不由模型猜测换算率 |
| RD-03 · P0 版本与快照 | 导入新版本或查询失败 | 同时记录业务发生时间和系统接收时间，保存来源版本和修订原因。版本冲突保留各自来源 | 已确认版本不得被过期来源覆盖。读取失败标出最近成功快照及时间，无快照则提示资料不可用 |
| RD-04 · P0 复核与审计 | 员工查看建议，授权人员复核 | 待确认事项记录问题、证据、当前状态。授权人员填写结论和理由，保存确认人、时间及所用版本 | 草稿与正式结论状态分开。权限不足禁止查看或确认。审计可定位访问人、版本、建议与确认人 |
| RD-05 · P1 AI 异常清单 | 员工请求核对一个批次 | 输入规则检查结果及授权来源，按站点、问题类别和待办汇总。每项提供单据名、版本、原行 | 输出待复核清单。证据不足标为待核实，模型失败时展示规则检查原表 |
| RD-06 · P1 AI 批次问答 | 员工在聊天中提问 | 检索前按角色与批次过滤。围绕出库、签收、换算和异常说明回答，引用可定位证据 | 找不到资料时说明缺口。拒绝越权查询。聊天及文档内容不能更改系统权限或触发外部动作 |
| RD-07 · P2 AI 来源候选 | 关联规则不能唯一匹配 | 在授权记录内，根据名称别名和字段相似度推荐候选，并展示匹配依据 | 仅展示候选供人工确认。低置信度时保留未关联，不自动建立正式关联 |

首期对业务源系统保持只读。系统内部可保存快照、核对结果和人工复核轨迹。源系统写回、外部消息、自动派单、食品安全、医疗补给与应急调度决策均在本期范围外。跨企业数据使用需另行授权。

## 5. 验收标准清单

| 编号 | 验证方式 | 通过标准 | 建议验收角色 |
| --- | --- | --- | --- |
| AC-01 | 对照冻结的 60 条验收样本逐条从出库反查站点 | 60/60 均可定位出库凭证及对应站点来源，抽检失败不得补写证据凑数 | 审核与质量负责人 |
| AC-02 | 另建异常用例，注入缺字段、重复编号、无匹配和多匹配 | 各异常均保留原行，进入人工队列，无默认通过 | 数字化工程师 |
| AC-03 | 输入已批准换算、无规则、冲突规则和过期规则 | 已批准规则计算与人工结果一致且可查看依据，其余情形全部拦截 | 业务负责人及审核负责人 |
| AC-04 | 回放追加物资未同步和旧版本晚到 | 显示冲突、双时间戳及原始版本。已确认的新版本不被覆盖 | 项目流程协调员 |
| AC-05 | 模拟读取失败，有快照和无快照各测一次 | 有快照时显示时间和失效提示，无快照时显示不可用 | 数字化工程师 |
| AC-06 | 核对验收结果及操作日志 | 60 条结果均有关联来源及人工复核记录。可定位访问人、版本、建议、确认人及时间 | 审核与质量负责人 |
| AC-07 | 以无权限账号访问批次、尝试确认，并测试写回或外部动作 | 越权访问和确认均被拒绝，外部业务系统无写入、消息或派单 | 审核与质量负责人 |
| AC-08 | 演练无法确认关键字段、暂停试点及删除到期资料 | 关键问题进入人工队列。授权人员可按审批条件暂停。按批准的期限和责任分工删除，审计链仍可核查 | 审核与质量负责人 |
| AC-09 | 对照同批次人工标注的缺项及版本冲突，逐项核查 AI 清单 | 测试集中预先标记的关键异常全部可见。每项有有效引用或明确待核实。模型失败时原表仍可访问 | 现场协调员 |
| AC-10 | 测试有依据、无依据、越权及注入指令四类问题 | 有依据的关键结论均可定位来源。无依据明确说明，越权和注入不能泄露数据或触发动作 | 业务负责人及审核负责人 |
| AC-11 | 对同一批次、同一任务口径记录改造前后工时、返工和确认完整率 | 三项均有原始测量记录，确认完整率不下降。工时和返工改善门槛在试点前签定，未签定前仅报告测量结果 | 业务负责人及客户协同代表 |
| AC-12 | 在独立标注集核对 AI 候选与人工确认结果 | 候选可复核、无自动关联。候选命中率门槛由评审确定后才进入 P2 验收 | 项目流程协调员 |

AC-01、AC-03、AC-06 对应访谈中的验收硬线。异常测试集与 60 条追溯样本分开保存。工时按参与人实际操作分钟累计，等待时长单列。返工按同一事项因资料差异或缺失再次处理计数。确认完整率为确认字段齐全的记录数除以应确认记录数，分母为零时记为不适用。历史材料的 12 站、80 条记录和 3 小时仅为演练口径，不能替代试点测量。

## 6. 评审决定与交付证据

- 顾明岚确认批次、站点、试点交接点、授权确认人和投入范围。访谈提及四周、两名业务骨干、每周不超过四小时，需明确四小时按人还是按团队计。
- 唐映秋与秦芮确认关联键、数据粒度、导出频率、有效期、版本交接和换算规则的定稿责任。落实 60 条验收样本的提供方、抽取口径与原始凭证位置。
- 傅景确认停止与恢复条件、留存删除规则及质量签署口径。叶书确认结果使用人、用途及效率评估方式。
- 验收归档包括样本清单及版本、批准的换算规则、人工预期、逐项测试结果、来源与确认日志，以及前后对照测量表。当前状态为待评审和待验证。
